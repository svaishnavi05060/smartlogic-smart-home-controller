// PROJECT FOUNDATION

Why this system matters

A smart-home controller is a practical model of a digital system: it reads conditions, evaluates logic, and changes physical outputs safely.

PROBLEM STATEMENT

Manual control wastes energy and delays safety responses.

Lights and appliances may remain active in empty rooms, while hazards such as unexpected movement or an open door need an immediate response. This project demonstrates how programmable logic can automate those decisions using simple, testable rules.

Core concept

Input sensors → Boolean logic → controller decision → output appliance

// DIGITAL THEORY

From Boolean expression to home action

Each sensor is treated as a binary input: 1 means the condition is present and 0 means it is absent.

01 / LOGIC

Essential operators

AND (·)

Output is 1 only when every required condition is 1.

OR (+)

Output is 1 when at least one condition is 1.

NOT (¬)

Inverts the input, turning 1 into 0 and 0 into 1.

FUNCTIONEXPRESSIONINPUT CONDITIONOUTPUT
Automatic lightM · DMotion AND darknessLiving light ON

SAMPLE EQUATION

L = M · D

Light turns on only if motion and darkness are both detected.

SECURITY EQUATION

S = A · (M + D)

Alarm responds in Away mode when motion or a door opening is detected.

ENERGY EQUATION

E = ¬M · T

Loads switch off when no motion persists beyond a timer threshold.

// IMPLEMENTATION GUIDE

Build the project in six stages

A structured workflow makes the prototype easier to explain, test, and troubleshoot during a college demonstration.

PLAN01

Define requirements

List sensors, appliances, thresholds, safety states, and expected outputs.

WIRE02

Design the circuit

Connect sensors to inputs and appliances through isolated relay outputs.

CODE03

Program the logic

Translate truth tables and Boolean expressions into controller conditions.

BUILD04

Integrate hardware

Assemble modules, label wiring, and confirm voltage levels.

TEST05

Test every state

Try normal, boundary, and failure cases against the truth table.

SHOW06

Present findings

Demonstrate automation, record energy observations, and explain decisions.

⚠
Prototype safety

Use low-voltage loads for classroom demonstrations. Mains appliances require rated relays, isolation, fuses, insulated enclosures, and qualified supervision.

// PROJECT EVALUATION

Benefits, constraints, and next steps

A strong report discusses not only what works, but also the limitations and realistic improvements.

GOOD

Advantages

  • Improves comfort and security
  • Reduces avoidable energy use
  • Rules are easy to modify
  • Demonstrates logic visibly
LIMIT

Limitations

  • Sensors can produce false readings
  • Remote control needs connectivity
  • Relay loads require isolation
  • A prototype needs calibration
NEXT

Future scope

  • Voice-assistant integration
  • Solar and battery optimization
  • Predictive automation
